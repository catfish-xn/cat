# v22 发布说明与测试服更新步骤（2026-10-24）

v22 把 10-23、10-24 批准的联机规则一次性上线：战斗数值、五费三星技能、强化、锻造器、黑市、经济节奏和开局奇遇都有变化。规则身份整体换新，**v21 及更早的存档和回放都不能在 v22 恢复**，更新前让在线的人先打完。

来源：PR #435（`claude/v22-integration` → `multiplayer`）。每条规则的批准日期和项目决定（P）记在 [S13_RULES_GAP](S13_RULES_GAP.md) 顶部各节，下面只讲玩起来有什么不同。

## 2. 规则变化

### 战斗

- **攻击力按星级单独成长**：普通英雄攻击力 1 星 / 2 星 / 3 星为 100% / 150% / 225%，生命值仍是 100% / 180% / 324%。以前攻击力跟着生命值一起涨，2、3 星打得偏疼。
- **六费攻击力**：沃里克 110/165/248，维克托 100/150/225，梅尔 80/120/180。六费生命值不变。
- **战斗时长**：每场最长 45 秒，第 30 秒起进入加时。加时每秒双方伤害和攻速增加，治疗、护盾和控制时长减少，移动速度固定 +50%。45 秒还没分出胜负算平局。
- **受伤回蓝**：每次受伤回 1% 减伤前伤害 + 3% 减伤后伤害（被护盾挡掉的也算），单次最多回 42.5 蓝。以前是掉血量的 3%、最多 20 蓝。
- **放完技能约 1 秒内不回蓝**；放技能时多出来的、不是受伤得来的蓝会保留。
- **暴击溢出**：暴击率超过 100% 的部分，按一半换成暴击伤害。

### 五费三星技能修正

- 赛维卡、玛尔扎哈、金克丝的三星技能按原版数值和范围修好（以前有的打不出来，有的范围不对）。
- 杰斯：目标被击飞到它身后约 3 格，再飞回原位，飞行路线上和两侧 1 格的敌人各挨一下。
- 莫德凯撒：技能挑能打中最多敌人的一条 8×3 直线。
- 安蓓萨：锁链冲向目标身边离自己最近的空格；已经贴着目标时站着不动。

### 杰斯的海克斯科技锻炉

- 杰斯在场上时，准备阶段他身后就有锻炉，可以拖到己方空格，位置每回合保留。
- 锻炉不能上备战席、不能卖、不能装备，不占人口。杰斯下场时锻炉跟着消失，再上场回到原来的位置。

### 强化（海克斯）

- **强化并入准备阶段**：2-1、3-2、4-2 不再单独停下来选强化。准备一开始就弹出三选一，这一回合准备时间合计 50 秒，期间可以照常买卖、刷新、上下场、装备。到时间没选，自动拿第一个。
- **档位表**换成 14.24 客户端的表（全桌共用同一套金/彩档位）。羁绊“天才”的强化从金色改为彩色。
- **按阵容过滤**：3-2、4-2 的羁绊强化，只有场上至少一个棋子有对应羁绊才会出现。2-1 不过滤。
- **互斥**：互相冲突的强化不会同时给你（比如有了安慰剂就不再出安慰剂+）。
- **见过就不再出**：给你看过的强化（包括刷新出来的），本局不会再给你，选没选都算。
- **安慰剂**按拿到的阶段一次给金币：2 阶段 8、3 阶段 11、4 阶段及以后 15；安慰剂+为 15 / 18 / 22。

### 锻造器（铁砧）

- 锻造器现在是**备战席上的一个单位**：不能上场，不占人口。拿到时如果备战席满了，就先留在法球里，有空位再去领。
- **想开的时候再开**：把它卖掉或拖到商店就打开，四选一，30 秒内选，超时自动拿第一个。倒计时由服务器算，断线重连不会重置。
- 奇遇、法球、史诗奖励里的锻造器都不会再自动弹窗。神器光辉（Radiant Relic）和便携锻炉（Portable Forge）还是当场四选一。
- 补给（选秀）回合不能打开锻造器，留到下个准备阶段。
- 4-7 野怪回合额外固定给 1 个散件锻造器，原有掉落不变。

### 黑市

- 黑市一开市就显示每个包里**具体是哪几件装备**，买下拿到的就是显示的那几件。

### 经济与回合节奏

- **连胜/连败金币**：2–4 连 +1，5 连 +2，6 连及以上 +3。野怪回合（包括开局）也算进连胜连败。
- **开局收入**：1-3、1-4、2-1 准备开始时的基础金币分别是 2、3、4，之后每回合 5。
- **准备时间**：1-2 为 6 秒，1-3 为 15 秒，1-4 和其他野怪回合 20 秒，4-6（异变）75 秒，强化回合 50 秒，其余 30 秒。

### 开局奇遇

- 第一批、第二批奇遇都已生效：梅尔、维克托、金币订阅和战利品订阅、安蓓萨的魔像训练师、沃里克的饥饿、迅捷蟹水潭、蟹之狂欢。
- **迅捷蟹的生命值**：每个野怪回合的蟹平分被替换掉的原野怪总生命（1-2 共 220、1-3 440、1-4 760、2-7 1200、3-7 2700、4-7 4800、5-7 6000、6-7 9000）。这是项目自定的数值，找到原版数据后会再改。
- 维克托奇遇会让普通对局的六费刷新概率也跟着变（第一批奇遇规则里批准过）。

### 顺带修的两个问题

- 开局第二批奇遇的升星事件以前会重复发两次。
- 打开过的战利品锻造器以前没算进“已有散件”，会影响相关判断。

## 3. 这一版没有包含的

- 3D 锻炉模型（`claude/jayce-forge-summon` 分支和素材 v10 增量包）没有进 v22，准备阶段的锻炉在 3D 里还是头像徽章。**这次 3D 素材不用换**，测试服现在用的那套素材继续用。
- 单机模式的锻造器 30 秒超时没做（单机不在范围内）。
- 已知小问题放到 v23：小种子下选择用的随机词有相关性；装备掉落里同一对象的引用顺序可能不稳定；杰斯离场后锻炉位置记录还留着（不影响玩法，有测试证明）。

## 4. 测试服更新步骤

按腾讯云测试服的布局写：根目录 `/srv/cat-playtest-v20`，对局服务 `cat-playtest-game`（8787），前端 `cat-playtest-web`（nginx，前端 5173、素材 5190）。**目录名或服务名不一样就换成实际的。同机其他服务一律不要动**，下面的命令只碰这两个服务和这个目录。

目标提交：**PR #435 合入后的 multiplayer 提交**，下文写作 `<V22_SHA>`（40 位完整 SHA，合入后协调者会给出）。上一版是 `920727234804a91cd8407cd506b9efd4fc3d67fe`。`package-lock.json` 和 `public/` 自上一版没变。

### 4.0 更新前检查

```bash
curl -s http://127.0.0.1:8787/healthz
```

`room` 是 `null`，或 `room.phase` 是 `ended`，才继续。有人在打就先等，重启会中断对局。

再看一下对局服务的配置：

```bash
systemctl cat cat-playtest-game
```

找到 `EnvironmentFile=` 指向的文件（或单元里的 `Environment=` 行），看 `CAT_` 开头的几项：

- `CAT_CHOICE_SEC`：如果是 `48`，改成 `30` 或删掉这一行。48 秒是 10-23 的旧决定，v22 已作废（强化改在准备阶段里选）。
- `CAT_PREP_SEC`：必须是 `30` 或者不设置。设成别的值，各回合的准备时间（6/15/20/75 秒）就全变成这个值。
- `CAT_SEED`（可选）：v22 起不设置就是每次启动随机。想让每次开服对局都不一样，就删掉这一行。保留的话，第一局用这个种子，之后各局由它派生。

改了配置文件就记下来，第 4.2 步重启时生效。改的是单元文件本身的话，先运行 `sudo systemctl daemon-reload`。

### 4.1 拉代码并构建

```bash

git fetch origin
git checkout --detach <V22_SHA>
npm ci
npm run build:game                  # 生成 dist-server/
VITE_CAT_SHA=$(git rev-parse HEAD) npm run build    # 生成 dist/
```

对局服务的 `CAT_GIT_SHA`（在 systemd 单元或 env 文件里）改成 `<V22_SHA>`。不改的话只是 /healthz 显示的 sha 不对，不影响游戏。

### 4.2 重启：先对局服务，后前端

```bash
sudo systemctl restart cat-playtest-game
curl -s http://127.0.0.1:8787/healthz       # status 要是 ok，contentDigest 是 2ee7d9d2
sudo systemctl reload cat-playtest-web      # 或 sudo nginx -s reload，按实际
```

浏览器打开下面的地址（IP 换成测试服公网 IP），**强制刷新一次**：

```
http://<IP>:5173/?mode=online&server=ws&render=3d&assets3d=http://<IP>:5190/assets3d/
```

服务器重启后，旧对局和旧座位都失效，玩家刷新后重新匹配即可。

### 4.7 上线前本机预检脚本（可选）

`scripts/live-precheck-v22.mjs` 在本机按 4.6 的方式起包（`dist-server/game/main.mjs` + `vite preview` 的 `dist/`，服务器全部用默认时长），开两个房间同时打真联机对局，每个房间 4 个浏览器玩家（playwright 驱动页面上的按钮和拖拽）+ 4 个机器人，自动检查 4.4 里的六项：

| 项 | 谁来做 | 看什么 |
| --- | --- | --- |
| 锻造器 | 房间 A（开局奇遇“基础装备锻造器”）的甲，1-4 | 备战席上的锻造器拖到商店 → 武器库 4 选 1、倒计时 30 秒，不选到点拿第一个 |
| 强化 | 甲、戊，2-1 | 准备一开始就弹出，准备 50 秒，弹窗开着能买棋子，到点拿第一个 |
| 准备时间 | 甲、戊 | 1-2 公布 6 秒、1-3 公布 15 秒，页面实际经历的时长 |
| 杰斯锻炉 | 谁先拿到杰斯 | 准备阶段把锻炉拖到另一格，下个准备阶段还在那格 |
| 加时 | 所有浏览器玩家自己的战斗 | 打过 30 秒的战斗截图；30 秒前后的移动间隔（5 tick → 3/4 tick）；打满 45 秒是平局 |
| 黑市 | 乙、己（只上炼金男爵） | 黑市包里每格都是具体装备，“全部拿走”拿到的就是显示的 |

```bash
npm ci
node scripts/live-precheck-v22.mjs                 # 先 build:game + build，再开打
node scripts/live-precheck-v22.mjs --no-build      # 已经构建过时
```

可选参数：`--minutes=70`（对局最长跑多久，默认 70 分钟；六项都有结论就提前结束）、`--seed-a=N` / `--seed-b=N`（换房间种子）。浏览器默认 `/usr/bin/google-chrome`，用 `CHROMIUM=` 换。端口自动找空闲的，不碰已有服务。

结果在 `artifacts/live-precheck/`（不提交）：每项的截图和 `report.json`（每条检查的证据、所有对局里自己战斗的时长）。终端最后打印每项 PASS / PARTIAL / FAIL / NOT-REACHED。杰斯、黑市靠对局走到那一步，没走到会是 NOT-REACHED，换种子或加长时间再跑一次即可；加时只有打过 30 秒、但没量到移动加快或没碰上 45 秒平局时是 PARTIAL（实战里过 30 秒的战斗单位多半站着打，45 秒平局很少见）。FAIL 才是问题。

2026-10-25 在 `2b434e28` 上本机跑过（种子 A=1152、B=64，约 26 分钟）：锻造器、强化、准备时间、杰斯锻炉、黑市 PASS；加时 PARTIAL（三场打过 30 秒，都在 32 秒内分出胜负，移动加快和 45 秒平局没在实战里出现）。
