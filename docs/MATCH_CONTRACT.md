# M3 Match contract v3

Public entrypoint `src/simulation/match.ts`; readonly types `match-types.ts`; rules `match-rules.ts`. Preserve M2 pure commands, explicit RNG/IDs and single settlement ownership. See M3_RULES.md for frozen numerical rules.

- `createMatch(seed=42)` validates uint32 including zero and returns a separate JSON-serializable schema3/rules m3-v1/content m3-content-v1 state. Fields include level/xp/playerHp, preparation, shop, RNG, serial and history.
- Existing buy/sell/reroll/deploy/start/continue signatures remain. New `buyXp(state)` takes no price/amount from UI. Success returns `{ok:true,state,events:MatchEvent[]}`, with unitUpgraded events for each merge. Rejections return `{ok:false,state,reason}` with the identical original state and no partial money/XP/RNG/ID/roster writes.
- `validateMatchDeployment(state,id,target)` is shared by preview and commit. It adds phase/population to unchanged GameState geometry and permission rules. Moving a board unit does not consume another population slot. Start rejects over-cap preparations.
- Preparation alone permits economic and deployment commands. F rejects in order wrong-phase, max-level, insufficient-gold; F never changes existing shop/generation/RNG. Only initial shop, successful D and Continue consume RNG, ten words each.
- Buy checks generation and purchased status before resources, then plans purchase+recursive triples atomically. Full bench is checked on the final plan. New candidate IDs consumed during merging are still never reused. Prices derive from definitions and star, never from UI.
- `stepMatch` consumes one50ms combat tick. Only terminal transition commits income/XP/HP/history. HP0 enters gameOver; otherwise settlement. Empty player deployment with enemies may start and immediately settle enemyWin at tick0; low-level validateCombatStart still reports missing-player for diagnostics.
- `nextRound(state,expectedRound)` only accepts a current settled round; no repeated reward. It refreshes shop using the already updated level, replaces only enemy preparation, preserves player units and positions, discards combat.
- GameOver rejects all normal commands including Continue. Outside combat, step returns identical state and no events. New Match discards the entire old match. Rendering never settles, calculates money, or repairs state.
- MatchSession delegates synchronously and holds only current MatchState plus fixed-step accumulator. Phase changes/finish/new match clear time remainder. Native D/F/E and pointer actions commit in event order, with no animation gate.
- Replay compares every state plus command/tick events, version metadata and logical tick order. JSON restores cannot depend on external settlement flags or RNG. Old M2 unversioned logs are intentionally incompatible with new costs, ten-word shops and combat mechanics.
