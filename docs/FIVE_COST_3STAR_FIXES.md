## 确定性、恢复与对外接口

- 新内部 `CombatTask.kind`：`g23Flame`、`g23Chomp`；沿用既有任务字段。`ordinal/total` 是当前已排任务的序号及上界，不代表整次无限引导的总跳数。`S13Packet.sevikaChomp` 仅为当拍结算标记，不进入网络事件。
- 序号、任务、活动、感染层均在 Combat JSON 中。`serialization-structure.ts:550` 增加两种任务，并只允许 `sevika-ability` / 本人 owner / `cancellable=true`；其他 G2 任务仍要求不可取消。没有放宽通用整数、唯一键、来源、时间或完整重演事实校验。
- 原本选招和百变铁手流保留，不添加新的抽样。连咬、传播、跳跃平手全部稳定排序。**同场总 RNG 词数可以因战局和后续普攻改变**；“无额外 RNG”指新增技能步骤不主动抽词，不承诺改变玩法后整战仍有相同总词数。
- 连咬以原施法 actionSeq/rootActionSeq 关联，斩杀通过既有 packetDamage/kill/death；仍按现有同步伤害屏障结算。下一 tick 连咬是项目既有延迟任务粒度，不宣称原版动画精确耗时为 50ms。
- 本次无 Match 公共命令、函数签名、失败 reason 或网络封套变动。同期 v22 必须录新的规则身份，再发布或恢复正式存档。

## 给 Claude 的接入点

不需要新增网络字段，不修改 `src/rendering/`。

1. `castOutcome.castVariant.move`、`actionSeq` 仍标识首招；喷火的 `channelTicks=40` 表示初始期限，不再是最终总时长。后续以现有 `activityChanged` 的 `refreshed`、`expired`、`control-cancelled`、`death-cleanup` 和权威活动状态驱动引导，不能 40 tick 到时强制播放结束。
2. 每次连咬沿用同一 actionSeq；下一目标与跳跃通过 `movement`、`packetDamage.outcome.context.targetId`、`rootActionSeq`/`triggeringCastActionSeq` 识别。没有额外独立 cast 收据/法力花费，不能自行抽招或把每跳计成一次玩家施法。
3. 感染层迁移体现在权威 tasks.targetId；伤害继续通过既有 packetDamage（归属 rootActionSeq）下发。现有显示投影不单发“感染迁移”特效事件，本次没有为它扩大协议；若需要逐层转移动画，应另列明确展示需求。
4. 本文列为暂停的三项几何保持旧行为，表现层不要先行扩展命中范围或替服务器算斩杀。
