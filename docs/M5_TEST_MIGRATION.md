# M5 test migration — A-owned economic and inventory tests

This records the migration of four test files from the M4 content/rule version to `m5-14.24b-v1`. It does not declare the full M5 acceptance suite complete. No production files were changed during this migration.

The pre-migration files are preserved byte-for-byte as `tests/historical/m4/{shop,progression,unit-stats,inventory}.test.ts.txt`. They are historical evidence artifacts, not executable M5 tests. The active tests remain at their original paths.

| Active file | Versioned change and independent expected-value basis | Preserved regression coverage |
|---|---|---|
| `tests/shop.test.ts` | Replace 18 placeholder units with R5's 19 heroes, in code-point order per cost bucket; L9 probabilities become 15/20/25/30/10 (R3). Newly generated shops are unlocked (R4). Explicit seed-42 sequences were independently recalculated with integer LCG arithmetic and the separately written catalog. The existing BigInt oracle imports no production RNG, odds, or catalog helper. | Ten draws, every probability boundary, within-bucket boundaries, duplicate offers, generation metadata, JSON restoration, immutability, seed/level/generation validation. |
| `tests/progression.test.ts` | R3 changes 7→8 to 48 XP and 8→9 to 76 XP. Hand-summed total 1→9 is 200 XP; 3→9 is 196 XP. Update the cap-edge example from XP79 to XP75, and L9 odds. | Below/exact/above every threshold, partitioned grants, multi-level overflow, requested versus applied XP at cap, normalized-state and invalid-input rejection. |
| `tests/unit-stats.test.ts` | The active shop is the 19-hero slice, while legacy and neutral definitions may exist outside acquisition pools. R3 sale values are explicitly transcribed as 1/3/9, 2/5/17, 3/8/26, 4/11/35, 5/14/44. Add independently specified Loris 40/80 mana and HP/AD star values. Missing active definitions, wrong cost, duplicate/empty catalog buckets, legacy/neutral catalog membership remain invalid. | All 18 legacy low-level stat-scaling cases, immutable snapshots, deeply frozen definitions, malformed attributes, illegal IDs (`__proto__`, `constructor`), illegal stars. | `tests/inventory.test.ts` | R5 has seven components and nine listed recipes. Replace the old complete 15-recipe table with these nine exact recipes and current IDs. Of 28 unordered pairs with repetition, 19 are unopened; every unopened pair is rejected in both argument orders. | Both recipe argument orders, reversed inventory order, stable consumed-ID order, serial allocation, stale/reused instances, equipped materials, completed-material rejection, invalid serials/IDs, three equipment slots, duplicate-release rejection, sale returns, JSON restoration and input immutability. |

Rule sources are the already-frozen references in `M5_RULES.md` R1/R3/R4/R5. These tests do not fetch a current online table, and do not call production calculations to manufacture numeric expected values. The updated shop goldens preserve the original RNG words; only their mapping into the explicitly changed catalog/probability table changes.

Actual verification for these four files: `npm test -- tests/shop.test.ts tests/progression.test.ts tests/unit-stats.test.ts tests/inventory.test.ts` passed **108/108** tests in **971 ms** on this run. File counts: shop 22, progression 26, unit-stats 42, inventory 18. Inventory's former 15 parameterized recipes became nine; one exhaustive unopened-pair test was added. No test was skipped. Full Match resource conservation, rejected command state identity, replay, normal-play routes and browser input remain separate gates.

## Follow-up: Match command economy

`tests/match-economy.test.ts` now begins through the public opening component/augment choices (`readyMatch`), using a non-gold-granting augment. `emptyBoard` moves the three initial deployed units to the bench through ordinary deployment commands. Focused unit fixtures still intentionally set gold/rosters to exercise boundaries; they are not normal-play route evidence.

The former 18-placeholder cost cases now cover all 19 M5 heroes. The nine-slot full-bench fixture explicitly includes a second Irelia to test a purchase completing an upgrade without a free slot. The 8+1 cascade uses a non-colliding next serial and still compares complete state and ordered events. First purchase serial changes from 6 to 4 because the M5 opening contains three units. F still preserves the existing shop generation; its following D is checked against an independently computed LCG sequence. Sell assertions use 4/11/35 for the selected four-cost, and XP cap fixtures use 75/76. Empty-board concession at 2-1 is independently expected to lose five HP (base two plus three enemies) and receive six gold at the tested eleven-gold balance.

`tests/fixtures/m5/command-oracle.cjs` preserves the old independent command model while consuming the separately authored M5 cost, sell, XP and shop oracle. It imports no production code and checks complete state/events for accepted commands. Its fixtures contain no equipped items or persistent growth; those systems require their own tests. Failure precedence, original-state identity, full-bench rejection, merge/cascade, serial monotonicity, zero-gold D/F burst, and combat/settlement/gameOver phase guards remain executable. A choice-phase guard was added. The original Match economy test is preserved separately under `tests/historical/m4` by the integration owner.

Combined actual verification after this follow-up: the five active files passed **150/150** tests in **1.53 s**, including **42** Match economy tests. This is targeted evidence only, not the complete M5 final gate.
