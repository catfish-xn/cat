## 双刀流来源与项目约定

原始中文：`获得2件符合该英雄定位的成装。` 原始英文没有自动穿戴要求。

- `map22` 中15个 `ScriptDataObject.mName = ItemKeyDefinition_CHARACTERROLE_*`，每池8项；逐项映射为当前实际成装id，没有删去未喜欢的装备或补造数值。
- `en_us.sets[13].champions[].role` 对应当前60英雄；固定表在 `src/simulation/content/s13-p1-dual-wielding.ts`，大小写规范化后精确匹配。测试遍历实际英雄集合，不用手列少数例子替代。
- **项目约定**：未找到直接将这些脚本池绑定双刀流的执行脚本；本批采用这些已有角色池。独立seed/choiceId/原始目标英雄标识派生显式LCG流，拒绝采样、无放回两次抽取。不会消费商店、强化选择或异常刷新RNG。
- **项目约定**：发入库存，不覆盖、不拆卸、不自动穿戴已有装备；同一批两件不重复，与已有装备允许相同。此表与角色映射进入CONTENT digest。
- **项目约定**：21个legacy/召唤物无官方role，固定显式角色表（无运行时猜测fallback）。3个当前召唤物使用APTANK，其余legacy按固定表；不把这些归为官方映射。
- 恢复先执行完整资源谱系校验，再取第一件授予前的合法资源前缀找到原始目标；沿后续升星消费/出售追踪到最终异常绑定。删除出生/收据、替换目标、改物品或来源轮次均拒绝。原目标已售出时仍根据历史前缀验证两件物品。

## 最小共用身份接口与剩余范围

`traceBoundUnitIdentity(originalId, verifiedFacts): string | null` 只沿**调用方已验证**的资源事实追踪升星幸存者和售出；不把未验证输入当可信。该接口可供P4继续使用，但不是猎头者的击杀收据、进入未知的暂离容器或终极英雄的4星实现。后续必须分别接真实事实与恢复，不能仅注册目录。

## 恢复与测试范围

基线仍是既有经济快照/收据校验，不宣称本批实现了缺失的B准备期完整命令重演。新增授予来源绑定选择身份；经济效果在当前已有结算事实中核对，未放宽原付费XP检查。非掉落/原G23选择入口不变；G23优先弹窗先处理，再打开尚未完成的强化forge。

`experiments/` 是明确撤出的未完整原型及历史日志，不编译、不入默认选择池，不计为实现完成。全部测试结果与最终head另见REPORT。

## 后续三个绑定单位异常：具体接续要求（未实现）

1. 猎头者：现有 `CombatEvent.kill` 的 `source.ownerId` 可区分亲自击杀与助攻；需在可信战斗重演时收集不同受害者id，形成每场 `{battleId, openingOwnerId, anomalyChoiceId, victims}` 收据。从已验证开战输入重演这些事实，再逐场累计攻速。`persistentGrowth.attackDamageBps` 当前只认证崔丝塔娜125基点步长，不能借该字段塞攻速或放宽其校验。上面的身份追踪可用于消费幸存者，但还缺独立AS增长类型、真实结算写入、历史重演核对及联机提案事实。
2. 进入未知：需 `{originalUnitId, choiceId, boundRound, returnRound}` 与真实拥有的暂离单位资源记录；从选择时确认3次已结算回合，不接受存档自报等待计数。棋盘移出、装备暂持、人口/羁绊投影与共享池仍计所有权，返回时需要空位及合并规则的实际实现。增益用现有AD百分比累加与AP加50。当前只保留设计，没有生产容器或服务器接线。
3. 终极英雄：需从选择时已验证3星1费目标、3次真实结算事实推导4星资格。`StarLevel`、编译、出售、升星消费、共享池份数（当前只1/3/9）、快照和恢复都需一致扩展，不能仅把显示星级改4。现有共享身份函数仅能追踪1→2→3的真实消费，不宣称实现四星。

这些都是本次指定项的必要工作，不是已经完成的功能，也没有通过未实现项的跨档位联机验收。后续应由Claude明确接续领域与服务器接口，不将未实现项直接注册上线。
