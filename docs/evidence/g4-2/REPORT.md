# G4-2 B8 中位数验收

基线：`origin/multiplayer@52c6a52`（包含 `4d2e70c`）；测试源码：`317887117790f6243f39a7f950dbbd48ff60a6c9`。

环境：Node `v22.23.3`，Vitest 5.0.3；G2 测试退出后在用户分配的独占时段顺序执行。timing 使用单 worker、文件串行、`isolate: true`。

battle 与 replay 各完整预热一次，再连续测五个新任务。startup 和每轮全部 `advance(1)` 中的最大耗时分别取五个样本的中位数，均断言 `< 50 ms`。原始样本全部保留于 [timing-five-runs.json](timing-five-runs.json)，未过滤离群值、未失败重试。

每类任务分为五个连续采样用例和一个中位数断言用例，采样用例保留默认 5000 ms timeout；预热放在 beforeAll。B8 从 1 个用例变为 12 个，完整 timing 从 21 个变为 32 个。1201 次推进上限及每次任务完成断言保留。

## 失败诊断与隔离调整

最初将预热和五次采样放进单个用例，replay 累计 6650 ms 超过默认 5000 ms；改为上述连续采样用例，未增加 timeout。

共享 worker（isolate:false）的首次完整序列第 1 轮通过（181.24 s），第 2 轮失败（178.58 s，31/32），replay longest 中位数 254.439 ms。该轮五个 longest 样本为 254.439、21.532、270.088、25.103、282.885 ms。随后独立进程 B8 五轮通过，replay longest 中位数为 21.10、19.91、19.57、20.04、18.44 ms。共享 worker 序列可复现长暂停，独立进程未复现；没有 GC trace，不能将原因确定为 GC。

因此 timing 恢复文件隔离，避免前序长测试的 worker 状态累积影响后续测量。上表是最终配置重新从第 1 轮开始连续执行的完整五轮，不包含之前的诊断成绩。隔离增加整套运行耗时；不主张已经达到旧 G4 的 180 s 总耗时目标。

生产代码、golden、50 ms 预算及默认测试 timeout 数字均未改动。中位数通过不表示每个原始样本都低于 50 ms。原始日志位于本地 ignored 的 `artifacts/g4-2*`；提交的 JSON 包含全部最终 B8 样本、通过计数、实际耗时与完整报告 SHA-256。
