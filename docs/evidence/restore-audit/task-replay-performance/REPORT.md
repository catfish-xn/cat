## m8-b7 新增时间的来源

`tests/m8-b7-match-wiring.test.ts:22` 的一个 `roundTrip` 检查点包含：

1. `serializeMatch(live)`：内部执行一次恢复校验。
2. `restoreMatch(saved)`：再执行一次恢复校验。
3. `serializeMatch(restored)`：内部再次执行恢复校验。

原分支 `serialization.ts:319` 明确为 `canonicalContent(restoreMatch(state))`。因此一个检查点会发起三次独立的完整队列认证；每次各重演一遍。跨调用缓存、减少检查点或跳过序列化中的校验都不符合本次约束。

本文件的普通中立战斗没有启用护臂增长或抗性护盾重演。共享候选没有可消除的同调用内重复重演。完整任务队列认证新增的单次重演必须保留；本次没有通过跳过空队列、按候选任务种类筛选、推断当前阵亡状态或放宽拒绝条件来提速。

600 tick 的护臂/石像鬼/抗性护盾组合诊断确实观察到：共享前护臂创建 1 次、推进 600 次，护盾再创建 1 次、推进 600 次，任务比较不推进；共享后总计创建 1 次、推进 600 次。诊断埋点的示例毫秒数只用于定位，不用来推断正式性能收益；正式结果采用下述无埋点串行测试。

整文件埋点共观察到 **605 次**进入战斗校验的恢复：护臂校验调用 605 次但重演 0 次；任务队列校验调用 555 次、创建战斗 **555 次**、推进 **27,462 tick**。每次最多创建 1 次，推进次数不超过保存 tick；其余 **50 次**在任务校验之前已拒绝。任务比较连同重演累计约 **15.049 秒**，护臂前置判断约 **11.8 毫秒**。此轮含埋点开销，仍有 30/30 用例通过，不纳入正式三轮耗时。
