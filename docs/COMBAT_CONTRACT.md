# M1 Combat Contract v1

Frozen before parallel implementation. Public API: `src/simulation/combat.ts`; types/constants: `combat-types.ts`. Preparation remains `GameState`. `createCombat(GameState): CombatState`; `stepCombat(CombatState): CombatStep` returns `{ state, events }`, without mutating inputs. Rendering imports only this API. `combat-tick.ts` is the simulation agent's private implementation.

- 20 ticks/s, 50 ms/tick, maximum 1200 ticks (60 logical seconds).
- Initial HP/attack from existing unit definitions. Flat attack damage; armor is not applied in M1. Sentinel/mystic range 1, ranger range 3, attack interval 20 ticks. First attack is ready immediately. Movement at most one hex every 5 ticks; ready immediately. At tick start cooldowns decrement to a minimum of zero; successful actions set their corresponding interval. Movement and attack may occur in the same tick.
- IDs must be unique. Valid preparation comes from existing deployment rules. Combat units and nested board/cell data are copied. No bench units, Phaser, DOM, wall time or randomness.
- Select nearest alive enemy by hex distance, then code-point ID order; reselect every tick. Snapshot occupancy includes all living units at movement phase start. BFS neighbors in existing E,SE,SW,W,NW,NE order to an empty cell in attack range; no path means wait and try next tick. Reserve destinations by ascending unit ID; losing movers wait. No swaps or stepping into cells occupied at phase start.
- Generate attacks from post-movement, pre-damage alive units; aggregate damage, apply simultaneously (HP clamped to zero), resolve deaths, then result. Retarget after movement if necessary using the same nearest rule. Stable event order: movements by ID, attacks by attacker ID, aggregated damage by victim ID, deaths by ID, then one combatFinished. Damage amount is total incoming raw damage; hp is remaining clamped HP.
- Dead units remain in state with alive=false, hp=0, no target and zero cooldowns; they no longer occupy cells. Resolve elimination before timeout; both sides eliminated is draw. If both sides remain at maxTicks, draw/timeout. Empty or single-sided starting boards finish at tick 0 (no step event needed; rendering reads state.result).
- Finished step returns identical terminal state and no events, no tick increment. Output units sorted by ID; permutations of input arrays must yield identical full state/events.
- Preparation -> combat -> result -> preparation is a rendering/controller lifecycle. Capture the current preparation at each Start; prohibit deployment/repeated Start outside preparation. Reset discards battle, accumulator, events and effects and restores this match's snapshot. Next battle creates fresh combat. Animation cannot affect rules.
- Phaser delta is accumulated; consume whole 50 ms ticks, retain remainder. Invalid/negative delta ignored. Any per-frame processing cap retains backlog. Test equivalent total time partitioning.

This document records the implemented decisions; M1_PLAN.md is preserved verbatim as requested, including its historical baseline notes.
