# 默认棋盘行列对齐

构建端的 locator 插值假设 `BoardLocator` 是首格，且
`BoardCenterLocator` 是 56 格的平均中心。这两个节点没有附带格号或行距；
原有测试只是重复该假设，无法发现网格与地面下沿之间的空隙。

离线检查地面网格、场景槽位、地图配置和六角指示器后，未找到能够独立
确定完整原版网格的格中心。指示器粒子的尺寸也不能证明相邻格中心距。
因此本次修复是可复现的**显示适配**，不声称还原原版客户端的格中心。
原版坐标、测量对照及素材根只保存在本地素材目录的 `row-align/`。

`boards-build.mjs` 对 `board-default` 使用 `boards-alignment.mjs`：

- 在棋盘中心、地面高度处，分别沿 z 和 x 发射截线，求地面材质
  `BattleField_A_MAT` 与墙材质 `Bench_A_MAT` 的交点。后者同时包含
  前后备战席墙及左右石头边框，并非所有名称含 Rock 的装饰物。
  两个方向均先应用源矩阵，再用实际索引三角形求交，不使用包围盒。
  地面必须跨过中心，且两侧必须各有地面范围内的墙交点；每侧选择
  最近中心的墙面，避开边框外侧及装饰几何。
- 将八排六角格的完整纵向包络适配到两墙之间。八排总高为
  `(7 × 1.5 + 2)r`，首尾排中心到墙各为 `r`，不另外添加偏移常数。
- 将七列的完整横向包络适配到左右墙之间。设格宽为 `w = √3r`，
  奇数行右移半格，完整包络宽为 `(7 + 0.5)w`，而非 `7w`。
  左右最外侧格中心到墙各为 `w/2`；与 z 向一致，四侧均为完整包络
  边缘贴墙，不添加额外空隙。错行另一侧的单行边缘会自然退入半格。
- x、z 原点各随实测两墙中点计算，不能假定与中心 locator 相同。
  保留 y 缩放和高度偏移，避免改变现有竖向放置；备战席源坐标及
  其他棋盘的算法不变。整个默认棋盘素材随新的 x/z 变换一起适配。
- 源素材 x、z 各自缩放；运行时网格保持正六角形，行距仍为
  `1.5r = √3/2 × 格宽`。`arenaTransform` 按半径统一重定向，无需修改。

`sourceGround`/`sourceGroundX` 分别记录 z/x 测量边界和推导性质；
`sourceLocator` 保留输入节点，`sourceFirstCell`/`sourceSteps` 记录
适配后的格中心及两个方向的间距。`deformation.scaleRatios.x/z` 分别为
新缩放除以旧 locator 缩放，减一后乘百分比得到相对原贴图显示的伸缩；
该基准仍是旧显示估计，不是已恢复的客户端格距。`xOverZ` 为新素材的
绝对 x/z 缩放比，`axisDifferencePercent` 为较大轴除以较小轴的偏离百分比。
构建 report 和 summary 的每个包均携带 alignment；summary 另列 deformation。
真实数值只保存在本地 `row-align/measurements-v2.json`，不写入仓库。
没有所需地面或墙三角形时构建报错；左右墙错误明确包含 `ground-x`，
不悄悄退回 locator 或包围盒拟合。`alignBoardGroundZ` 保留为单轴适配函数，
默认棋盘构建改用 `alignBoardGroundXZ`。

本地复现使用 `row-align/rebuild-v2.mjs` 从原压缩棋盘重建 metadata、
precache 和完整素材根，输出 `board-default-v2/` 与 `asset-root-v2/`；
新目录已存在时拒绝覆盖，旧 `asset-root/` 保留。路径检查模块保持不变。
`screenshots-v2.mjs` 使用原版 multiplayer 的 locator 变换作 before，
固定旧脚本的相机、视口和六角叠加样式，输出 `before.png` 与 `after-v2.png`。
截图仅展示静态原素材与运行时网格叠加，不代表完整游戏 UI 验收。

回归测试完全使用合成地面、墙、源矩阵和独立指定的格中心，覆盖首尾墙边距、
左右倾斜墙截线、7.5 格宽、56 格映射、半径/原点变化、无关几何及
缺失地面、双侧或单侧墙证据。真实原版格距仍属未知；
将来若获得格中心或明确布局参数，应优先替换几何拟合。
