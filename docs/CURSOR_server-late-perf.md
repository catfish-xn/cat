# 后期回合服务器耗时与回放前缀复制

测量基线是 `cursor/v26-integration` 的 `0ebf828f8ca7937edf1f94a8945a92989fdf03d8`。测量期间该分支又前进到 `7ff86a469bca6e57030ec24a7a21e81d32ac8e40`。两提交之间 `src/server` 与 `src/simulation` 没有差异，下面的房间耗时和房间 JSON 仍对得上当前服务器代码。Node v22.23.4。没有 `--write`，没有改超时、断言或校验。

## 测法

`scripts/profile-server-late-perf.cjs` 只在脚本里读 `performance.now()`。`src/server` 没有新增 `setTimeout`、`Date.now`、`performance.now` 或 `window`。

八席机器人 `b0`–`b7`，种子 42，`combatStreaming`，`sliceTicks` 100，`sliceMs` 20，守恒检查开着。八个订阅者对每个席位做 `toPlayerView` / `toSeatPrivateView`，并只 JSON 序列化新的战斗块。整轮「推进」是该回合全部时钟回调的同步 CPU 之和，不是阶段的墙上时长。`replace` 的「发布」包含这次发布里的投影、视图 JSON 和守恒检查，这几项互相重叠，不能相加。回合边界的显式 GC 和房间 JSON 哈希在回调计时之外。

## 改了什么

`replayTail`（`src/server/room/live-bank.ts`）以前对前缀里每一帧都 `JSON.stringify`。实时银行的 `pushLive` 用 `[...已发送前缀, ...新帧]` 拼修订回放，未改动的前缀帧是同一批对象。现在先用引用相等跳过，引用不同才序列化。分歧下标与终端比较的结果不变：同一对象必然 JSON 相同；不同对象仍按 JSON 判断。

`tests/server/replay-tail.test.ts` 增加了一条断言：共享引用的后缀从第一条新帧开始；JSON 相同但不是同一对象的副本整段视为相同；副本里改一帧时，尾部从那一帧切到末尾。

客户端的 `[...前缀, ...新块]` 和 `every` 引用扫描没有改。试过用持久化块树代替整段展开，在同一批块长度上比 V8 的密集数组展开更慢，已撤回。见下文。

## 回放前缀复制

生产路径不是深拷贝。

- 客户端 `ws-client` 每个战斗块做 `[...last.ticks, ...新帧]`，`remote-session` 再用 `every` 做引用比较。块长为 2 时，这是按 tick 的 O(T²) 指针复制。
- 整局 15,655,851 次指针复制和同样次数的引用比较。改前那次配套测量：展开 29.4 ms，扫描 40.1 ms，合计 69.5 ms。最重的一轮是 2-5，10.6 ms / 1,053,932 次。帧再大也不增加浅拷贝的成本。
- 服务器 `replayTail` 才按帧做 JSON。`pushLive` 的未改前缀是同一引用。合成负载（1500 帧、每帧 2134 字节、重复 20 次）：全量 JSON 321.5 ms，引用短路 1.08 ms，分歧下标都是 1500。200 帧内容相同但不是同一对象：42.3 ms 对 41.4 ms，下标都是 200。短路没有把「内容相同的副本」当成已经比较过。

持久化块树（追加只复制树脊、前缀判断走追加链）在同一块长度上没有更快：忙时展开加扫描约 153 ms，树约 151 ms，建树本身比密集数组展开慢。Proxy 随机访问还更贵。因此没有改客户端。

## 没改的原因

- `advanceS13Tick`、`copyCombatUnitForTick`、`unitView`、回放 `record`：这是后期 CPU 的主体，跟场上单位数走。少拷一帧会改回放字节。要单独证明 JSON 不变才能动。
- `assertSharedPoolConservation`：自身约 1.5%。不能关、不能放宽。
- `freezeOwned`：内容身份。改共享方式会碰冻结对象。
- `appendResourceProvenance` 每次把已冻结的 `entries` 展开成新数组。这是不可变快照，改成绳子会碰存档字节。
- `pushLive` 仍分配一条新的 `ticks` 数组。这是存下来的修订回放，浅拷贝，下一刀差分要用。贵的是原先对这条前缀的 JSON，已经去掉。
- `toCombatReplayFor` 命中缓存时帧是同一对象。新的对战对象会重建帧，那些帧引用不同，仍走 JSON。不能改成只比引用，否则内容相同的副本会被当成整段都变了。
- 八席公开视图在每次 `replace` 里全量投影。`toSeatPrivateView` 已按 Match 引用做 WeakMap。再做成增量视图要先锁住线上 JSON，本次没有证明。
- 20 ms 切片切不开单次重 tick。没有加超时。
