# 后期回合服务器耗时与回放前缀复制

基线是 `claude/v26-integration` 的 `c9b30bc7e81f0446a2c72d87b762fbdd01e5f49a`（Merge claude/v26-damage-fx into v26 integration）。测量时远程另有 `cursor/v26-integration`（`7ff86a46`），按本次更正没有用它。Node v22.23.4。没有 `--write`，没有改超时、断言或校验。`src/server` 没有新增 `setTimeout`、`Date.now`、`performance.now` 或 `window`。

## 测法

`scripts/profile-server-late-perf.cjs` 只在脚本里读 `performance.now()`。八席机器人 `b0`–`b7`，种子 42，`combatStreaming`，`sliceTicks` 100，`sliceMs` 20，守恒检查开着。八个订阅者做 `toPlayerView` / `toSeatPrivateView`，并只 JSON 序列化新的战斗块。

整轮「推进」是该回合全部时钟回调的同步 CPU 之和，不是阶段的墙上时长。「发布」是 `replace`，里面含这次发布的投影、视图 JSON 和守恒检查，这几项重叠，不能相加。回合边界的显式 GC 和房间 JSON 哈希在回调计时之外。CPU profile 含它们。

对局在 6-5 结束，最后一人存活，没有加时。36 个有名字的回合。

## 改了什么

`replayTail`（`src/server/room/live-bank.ts`）以前对前缀每一帧都 `JSON.stringify`。`pushLive` 用 `[...已发送前缀, ...新帧]` 拼修订回放，未改动的前缀帧是同一批对象。现在先用引用相等跳过，引用不同才序列化。终端同样先比引用。分歧下标不变：同一对象必然 JSON 相同；不同对象仍按 JSON 判断。

`tests/server/replay-tail.test.ts` 增加一条断言：共享引用的新帧从那一帧开始切；JSON 相同但不是同一对象的副本整段视为相同；副本里改一帧时，尾部从那一帧切到末尾。

客户端的 `[...前缀, ...新块]` 和 `every` 引用扫描没有改。

## 回放前缀复制

生产路径不是深拷贝。

- 客户端 `ws-client` 每个战斗块做 `[...last.ticks, ...新帧]`，`remote-session` 再用 `every` 做引用比较。块长多为 1–2 帧，所以这是按 tick 的 O(T²) 指针复制。
- 整局 10,308,039 次指针复制和同样次数的引用比较。配套测量：展开 24.6 ms，扫描 27.1 ms，合计 51.7 ms。最重的一轮是 2-1，7.17 ms / 533,806 次；指针次数最多的是 2-5，786,678 次。帧再大也不增加浅拷贝成本。
- 用「只追加块引用、不复制帧」在同一批块长度上重测：块列表复制 20.2 ms / 10,248,639 次，和帧展开 22.7 ms 差不多。块只有一两帧时，块列表的长度和帧数同阶，换结构省不下来。因此没有改客户端。
- 服务器 `replayTail` 才按帧做 JSON。合成负载（1500 帧、每帧 2134 字节、重复 20 次）：全量 JSON 327.2 ms，引用短路 1.21 ms，分歧下标都是 1500。200 帧内容相同但不是同一对象：42.8 ms 对 42.3 ms，下标都是 200。短路没有把副本当成已经比较过。

## 没改的原因

- `advanceS13Tick`、`copyCombatUnitForTick`、`unitView`、回放 `record`：后期 CPU 的主体，跟场上单位数走。少拷一帧会改回放字节。
- `assertSharedPoolConservation`：包含约 2.9%。不能关、不能放宽。
- `freezeOwned`：内容身份。
- `appendResourceProvenance` 每次展开已冻结的 `entries`。这是不可变快照，改成增量结构会碰存档字节。
- `pushLive` 仍分配一条新的 `ticks` 数组。这是存下来的修订回放，浅拷贝。贵的是原先对这条前缀的 JSON，已经去掉。
- `toCombatReplayFor` 命中缓存时帧是同一对象。新的对战对象会重建帧，那些帧引用不同，仍走 JSON。不能改成只比引用，否则内容相同的副本会被当成整段都变了。
- 八席公开视图在每次 `replace` 里全量投影。再做成增量视图要先锁住线上 JSON。
- 20 ms 切片切不开单次重 tick。没有加超时。
